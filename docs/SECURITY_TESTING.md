# Customer, authentication and cart integrity checks (#47)

Run `php scripts/check-authorization.php` against a disposable MariaDB server. Set `SCHEMA_TEST_HOST`, `SCHEMA_TEST_PORT`, `SCHEMA_TEST_USER` and `SCHEMA_TEST_PASS` as needed. The test user needs CREATE and DROP DATABASE permission. The script creates a randomly named test database, loads the synthetic schema and seed, starts a temporary loopback PHP server, then removes its database and server. It does not read the application's `.env`.

The checks cover duplicate registration, wrong password and unknown email, missing/malformed/unknown/expired/revoked bearer tokens, inactive accounts, cross-user profile and cart access, foreign cart items, unauthorized deactivation, staff restrictions and caller-supplied role/owner fields. Denied writes compare the contents of customers, carts, cart items, products, categories, orders and order items before and after the response. Authentication attempts legitimately change login-limit records, so those counters are not included in that resource snapshot. Responses are checked for expected status, bearer challenge on 401 and absence of token and credential field names.

The same script exercises representative order ownership, checkout and catalog role denials, and `scripts/check-order-concurrency.php` covers concurrent checkout and a cart write racing with deactivation. These are integration checks using real MariaDB and synthetic accounts, not substitutes for the resource owners' full test evidence.
